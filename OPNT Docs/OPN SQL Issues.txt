NEW PROBLEM DISCOVERED:

The STD process is creating KWs out of scrapes - but the scrapes are URLs and can go to any length - but the max of KEYWORDS column is 160. Moreover, it is a primary index and the MySQL seems to stop the index at length 64. This is causing the KWs to be truncated or being found dupes (such as 'https://timesofindia.indiatimes.com/entertainment/hindi/bollywoo') - this needs to be fixed at the proc level:

- the convertPostToKW proc - it needs to use the NEWS_HEADLINE to create the KW - instead of the NEWS_URL
- this means, the post_content in opn_posts will carry the full url and the full url will also be stored in the KW_URL column of the OPN_P_KW
- This can still run into cinflict (where the news headline is itself repeated and runs into primary key conflict - such as 'trump wins' )
- so, in the WSRL Dedupe all, we should add a step where if stbstr(news_headline, 1, 64) already exists in the OPN_P_KW, then we should just kill that scrape.
